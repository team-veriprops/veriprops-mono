## Executive Summary

Veriprops ("Verified Properties") is a property-verification platform for the Nigerian diaspora.
A customer submits a property, pays (gateway-mediated, NGN-contractual), and a tiered set of
independent agents (Field / Surveyor / Registry / Lawyer) perform role-scoped tasks under
admin orchestration. The output is a versioned, defensible **Report** carrying a **Trust Score
(0–100)** and a public-safe **Verification ID** (`VP-YYYY-XXXXXX`). The product's core asset is a
deterministic, fully-audited state lifecycle and an evidence trail strong enough to defend
chargebacks and disputes.

The PRD is organised as a **phased implementation spine (Phases 0–19)**. Phases 0–10 are the MVP;
11–19 harden and scale. Three companion artefacts cut across all phases and are authoritative:
**§2 state machines**, **§4 architecture decisions**, and **§A/§B resolved/open decisions**.

**Current build state (brownfield audit):**
- **Backend foundation (`appodus_utils`) is largely in place:** `BaseEntity`, `GenericRepo` +
  `Page[T]`, `@transactional`, Kink DI, `Money` (integer minor units), `AuditLog`,
  `ConsentDocument`/`UserConsent`, JWT-cookie auth, OAuth popup, OTP, KYC provider settings.
- **Most domain code is staged for deletion** (verification, payment, payout, commission, referral,

- **Migration `0001_initial_schema.py` still defines/seeds the deleted domains' tables** (tiers,

- **Frontend:** auth ~95% (multi-step signup, login, OAuth popup, OTP, `data-testid`, automation

**Strategy (D1):** brownfield build-forward. Reuse the surviving foundation and frontend assets;
rebuild deleted domains phase-by-phase, **aligning new domain models to the existing `0001`
schema** rather than recreating tables.

## Goals

- Make "verified property" the default belief in the Nigerian market ("If it's not verified, nobody buys it").
- Deterministic, audited verification lifecycle: four state machines (§2, §4.7), one state-derivation owner (§4.1).
- Defensible legal posture: versioned consent, 1× fees liability cap, agent indemnity, report disclaimer (§3.5).
- Diaspora-first money model: NGN-contractual, gateway-mediated, no FX risk, integer minor units (§4.4).
- Trust-building transparency: live tracking, evidence layer with content hashes, interim reassurance (§9).
- Marketplace health: agent earnings with clearance/reserve, reputation, coverage, growth loops (§15–17).

## Non-Goals (MVP)

- Listing-URL import (removed — brittle scraping, §17.x).
- Auto-deduplicated property identity layer (Post-MVP; structural separation only, §4.3).
- Escrow / purchase-transaction layer (Post-MVP, separate regulated product).
- Full event sourcing (explicitly not adopted; real `status` column + `AuditLog`, §4).
- WebSocket duplex realtime (SSE-only by design, §4.9); WhatsApp delivery; native mobile apps.
- PI-insurance posture and per-market cross-border enforceability (deferred to §B; gate Premium lawyer + Phase 10).

## High-Risk Areas

- **State-derivation correctness (§4.1, §2.5):** single owner; dependency-blocked Lawyer task must be
  counted from tier config, not `COUNT(tasks)`. Wrong = "dashboard says X, admin says Y" bugs.
- **Money & FX (§4.4):** integer minor units everywhere; contractual NGN vs charge currency separation;
  refunds re-converted by card network; reconciliation to the kobo across pay→refund→commission→payout.
- **Idempotency (§4.6):** duplicate gateway webhooks must not double-`PAID` or double-receipt; entity-create
  double-taps on flaky mobile networks.
- **Fraud-hold messaging (§4.7):** synchronous scan, fast-lane for clean messages, hold only flagged;
  non-accusatory copy; false-positive instrumentation from day one.
- **Legal gates (§3.5, §B):** liability-cap language **blocks Phase 5**; NBA counsel sign-off **gates Phase 10
  Legal Opinion go-live**; Premium lawyer insurance posture gates that tier.
- **Evidence integrity (§4.5) + proof-of-presence (§7.3a):** server-side GPS/timestamp stamping; content hash
  over retained full-res original.
- **Brownfield reconciliation (D6):** rebuilt domain models must match the `0001` schema; risk of drift.
- **Offline agent upload queue (§7.4):** genuinely hard; scoped to Field/Surveyor.

## Cross-Cutting Concerns

- **Auth:** JWT httpOnly cookie (15-min access / 30-day refresh), silent refresh, OAuth popup + postMessage,
  centralised Next.js proxy route protection (cookie-presence; validity server-enforced per call). `user_type`
  (USER/ADMIN, immutable) vs `user_persona` ([CUSTOMER, AGENT], additive). Trusted status on first payment/submission.
- **Data model:** PostgreSQL (async SQLAlchemy + Alembic). camelCase API serialization (`to_camel`) ↔ snake_case
  Python; frontend types camelCase, no transform layer. Property separated from Verification (§4.3).
- **Determinism / derived state:** four state machines; one derivation owner (§4.1); no endpoint sets status directly.
- **Audit:** every transition logged (entity, actor, role, from→to, ts, IP, note); evidence carries content hash;
  retained indefinitely; NDPA erasure via pseudonymisation (§4.11).
- **Idempotency:** keys for payments + entity creation; optimistic locking (`version`) for updates (§4.6).
- **Real-time:** SSE for all server→client pushes + 60-sec polling fallback; HTTP POST for sends (§4.9);
  in-process synchronous event bus with declarative fan-out rule table (§4.8).
- **Observability / compliance:** structured exceptions (`AppodusBaseException`); NDPA retention (`pii_retention_days`),
  erasure workflow; mobile-first, low-bandwidth weight budgets; embedded education tooltips.

## System Implications

### Database
- PostgreSQL, async SQLAlchemy, Alembic. Single squashed migration `0001_initial_schema.py` already
  defines the full schema (incl. deleted domains). **Rebuilds must align models to this schema (D6)**;
  prefer additive migrations over recreating tables.
- New/confirm tables for: Property, Verification, Task, TaskEvidence, Report, Payment, Commission, Payout,
  Referral, Notification, Thread/Message + fraud holds, Conflict rules, AdminConfig, Retention/Erasure.
- All money columns integer minor units + currency code. Optimistic-lock `version` on `BaseEntity`.

### API
- FastAPI controllers per domain; camelCase serialization; pagination via `page`/`page_size` → `Page[T]`.
- Backend↔frontend contract kept in sync per CLAUDE.md (rename/add/remove endpoint = change both ends in one PR).
- Customer-facing endpoints expose only `role`, `first_name`, `avatar_url`, `verified` for agents (enforced server-side).
- Idempotency-key header handling on payment + entity-creation routes; idempotent gateway webhook handler.

### Security
- Public lookup (`/verify/[id]`) is an enumeration surface: non-sequential VIDs, rate-limiting, indistinguishable
  responses (§4.10). OAuth: single-use signed state (Redis delete-on-read), PKCE S256, strict redirect-URI,
  origin-allowlisted postMessage. KYC biometrics deferred to provider (Dojah facade). NDPA: minimised third-party
  PII, lawful-basis recording, pseudonymised audit on erasure.

   evidence content-hash helper, SLA/holiday calendar. Verify auth/foundation survivors.

   **Phase 7** agent execution → **Phase 8** review/release → **Phase 9** tracking/evidence → **Phase 10** report.
